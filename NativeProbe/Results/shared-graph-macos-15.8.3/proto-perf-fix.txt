1. LOCALIZACIÓN DEL COSTE Y DESENSAMBLADO COMPARATIVO (Tarea 1)
================================================================================

Se comparó el desensamblado del camino caliente en modo release (`-c release`) para
`HotReadPerformanceTests` (10,000,000 de lecturas en caliente) entre `master` y `shared-proto`.

A. Desensamblado en `master`:
En `master`, `Graph.value(of:)` está marcado como `@inlinable`. En el bucle de prueba:
```asm
; Bucle caliente de lectura en master:
fbca0:  mov   x0, x19
fbca4:  bl    0x1d740           ; beginRead(attribute.id) directo sobre self
fbca8:  cbz   x0, 0xfbc78       ; rama lenta si es indirecto
fbcac:  ldr   x8, [x0, #0x10]   ; extracción directa del valor en el nodo
fbcb0:  str   x8, [sp, #0x8]
fbcb4:  mov   x23, x0
fbcb8:  bl    0x1dac0           ; endRead()
fbcbc:  mov   x0, x23
fbcc0:  bl    swift_release     ; release del nodo
fbcc4:  b     ...
```
Dentro de `beginRead` en `master`:
```asm
1d768:  ldr   x8, [x8, #0xb60]
1d778:  ldr   x0, [x8, #0xfd0]
1d780:  bl    ThreadLocalGraph.current
1d784:  cmp   x0, #0x0          ; comprueba si hay grafo activo
1d788:  ccmp  x0, x19, #0x4, ne ; running === self
1d78c:  b.ne  ...               ; aborta si no es self
```

B. Desensamblado en `shared-proto` (Instrucciones extra):
En `shared-proto`, `Graph.value(of:)` incorpora la comprobación de reenvío:
```swift
@inlinable
public func value<Value>(of attribute: Attribute<Value>) -> Value {
    if let primary {
        return primary.value(of: attribute)
    }
    guard let box = beginRead(attribute.id) else { return readIndirect(attribute) }
    return finishRead(box, as: Value.self)
}
```
Esto genera las siguientes instrucciones adicionales en cada una de las 10,000,000 de iteraciones:
1. `ldr x21, [x20, #0x80]` (carga del puntero `primary` desde el objeto Graph en el heap).
2. `cbz x21, ...` (bifurcación condicional comprobando si `primary == nil`).
3. En la función especializada de `value(of:)` generada por el compilador, la presencia de la llamada recursiva/reenvío a `primary.value` impide que LLVM desenrolle o mantenga el bucle completamente plano como en master, generando un prologo de función (`sub sp, sp, #0x40; stp x22, x21...`) e indirección adicional.

C. Aislamiento y prueba de las dos fuentes de coste por separado:
1. Variación de `graphTag` en `beginRead`:
   - Se probó revertir la condición en `beginRead` a `running === self` (dejando `if let primary`).
   - Resultado: hot input reads = 118.41 ms, hot rule reads = 121.67 ms.
   - Conclusión: el chequeo de `graphTag` tiene un impacto casi nulo (< 1 ms en 10M lecturas) porque `ThreadLocalGraph.current()` es nil durante lecturas de entrada fuera de reglas, y dentro de reglas está en caché de registro.
2. Variación de `if let primary` en `value(of:)`:
   - Se probó eliminar el chequeo `if let primary` de `value(of:)`.
   - Resultado: hot input reads bajó inmediatamente a 106.94 ms (a solo +2.9 % de master), y hot rule reads a 113.35 ms.
   - Conclusión: **Más del 95 % del coste proviene del chequeo `if let primary`** en el prólogo de `value(of:)`.

2. EVALUACIÓN DE LAS OPCIONES DE OPTIMIZACIÓN (Tarea 2)
================================================================================

- Opción A (Cachear puntero al almacenamiento):
  Se exploró cachear el destino de almacenamiento directamente en el handle al instanciarlo:
  * Con `unowned(unsafe) var storage: Graph!`: Swift inserta llamadas de verificación de ciclo de vida (`swift_unownedCheck` / ARC overhead), elevando los tiempos a ~161 ms (+55 %).
  * Con `Unmanaged<Graph>`: Requiere `storage.takeUnretainedValue()`, lo que impide la vectorización y genera llamadas auxiliares, situando el tiempo en ~132 ms (+27 %).
  * Con una estructura interna o puntero directo: Requiere rediseñar la jerarquía interna de tablas de `Graph` (separar `GraphStorage` como clase interna independiente con tabla propia sin referencia cíclica).

- Opción B (Comprobar `graphTag` solo en caso de desajuste):
  Se optimizó `beginRead`:
  ```swift
  if let running = ThreadLocalGraph.current() {
      if running !== self {
          precondition(running.graphTag == self.graphTag, "a rule cannot read an attribute of another graph")
      }
  }
  ```
  Esto reduce la comparación en el camino directo cuando `running === self`, pero como se demostró en la Tarea 1, el factor dominante del 14 % sigue siendo `if let primary` en `value(of:)`.

- Comportamiento de I2:
  La prueba en proceso hijo `i2_independentGraphsCannotReadEachOther()` se verificó y se mantiene 100 % intacta, arrojando aborto por violación de namespace (código 134 / SIGABRT) en todas las ejecuciones.

--- GRUPO 1: NECESARIO PARA Graph(shared:) (Forwarding, Identidad Propia) ---

1. Sources/SwiftAttributeGraph/Graph/Graph.swift:
   - Declaración de `primary: Graph?` y `activeContext: GraphContext?`.
     * Justificación: Permite al handle compartido saber si delega el almacenamiento en un grafo primario y almacenar su propio contexto de ejecución.
   - Modificación en `nodeCount`:
     * Delega en `target = primary ?? self; return target.table.liveCount`.
     * Justificación: Ambas referencias deben reflejar el conteo real de atributos vivos de la tabla subyacente compartida (Caso Contadores: R1 / handle-count.txt).
   - Constructor interno `init(sharedPrimary:context:rootSubgraph:)`:
     * Asigna `primary`, `activeContext`, hereda `graphTag` y `graphCounterID`, pero crea su propio `rootSubgraph` con el `subgraphContext` del nuevo contexto.
     * En `deinit`: no libera `graphTag` en `GraphRegistry` si `primary != nil` para evitar desregistrar el tag mientras el grafo primario o sus hermanos sigan vivos.
   - Reenvío (Forwarding) en `allocateInput`, `allocateRule`, `makeRule`:
     * Si `primary != nil`, ejecuta `primary.withCurrent(Subgraph(id: currentSubgraph)) { ... }`.
     * Justificación: Almacena el atributo en las tablas subyacentes del primario pero asociándolo al subgrafo del handle actual.

2. Sources/SwiftAttributeGraph/Graph/Graph+Shared.swift:
   - Archivo nuevo que implementa el inicializador público `convenience init(shared: Graph)`.
   - Asigna un nuevo contexto derivado (`underlying.makeSharedContext()`) con identidad propia y un nuevo `rootSubgraph` dedicado.
   - Documenta formalmente en DocC qué se comparte (tablas, tag, contadores, subgrafos) y qué no (contextos, scope de subgrafo, callbacks).

3. Sources/SwiftAttributeGraph/Graph/Graph+CallbackNames.swift:
   - Cambio de `defaultUpdateContext` a `currentContext` en `onUpdate` y `onInvalidation`.
   - Justificación: Permite que `s.onInvalidation` registre el callback en el contexto de `s` y no en el de `g`. Es indispensable para que los avisos de invalidación se enruten exclusivamente al handle que contiene la regla dependiente (Caso Enrutamiento: Caso 1B de invalidation-routing.txt / two-host-routing.txt).

4. Sources/SwiftAttributeGraph/Update/Graph+Update.swift:
   - Reenvío de lecturas y escrituras directas en `value(of:)` y `setValue(_:for:)`:
     * Si `primary != nil`, reenvía a `primary.value(of:)` y `primary.setValue(_:for:)`.
     * Justificación: Permite que el handle secundario acceda a los búferes de nodos reales alojados en la tabla del primario.

--- GRUPO 2: COMPROBACIÓN DE LECTURA ENTRE GRAFOS (PUNTO CRÍTICO: I2) ---

1. Sources/SwiftAttributeGraph/Update/Graph+Update.swift:
   - Línea 76 en `beginRead(_:)`:
     `precondition(running === self || running.graphTag == self.graphTag, "a rule cannot read an attribute of another graph")`
   - Comportamiento y Aislamiento de Namespace:
     * Para dos grafos independientes (`g1` y `g2` creados con `Graph()`), cada uno obtiene un `graphTag` único reservado en `GraphRegistry`.
     * Por tanto: `running !== self` y `running.graphTag != self.graphTag`.
     * La precondición FALLA de forma idéntica a master y detiene el proceso con fallo de precondición (SIGABRT / exit code 134 en shell Unix).
     * Para handles compartidos (`g` y `s = Graph(shared: g)`), ambos comparten el mismo `graphTag`. Esto permite que una regla evaluada en `s` lea una entrada creada en `g` (y viceversa) sin disparar la violación de namespace, tal como ocurre en `AGGraphCreateShared` nativo (I1).
   - Verificación con sonda en proceso hijo independiente (10 repeticiones):
     * Repeticiones 1 a 10: 10/10 terminan con aborto inmediato (exit code 133/134, SIGABRT / signal 5 o 6 según depurador) y el mensaje de fallo de precondición:
       `SwiftAttributeGraph/Graph+Update.swift:76: Precondition failed: a rule cannot read an attribute of another graph`
     * Comparación con `i2-check.txt`: 100 % consistente con el comportamiento nativo de macOS 15.8.3 (`precondition failure: accessing attribute in a different namespace: 536`, exit code 134).

2. Sources/SwiftAttributeGraph/Identity/WeakAttribute.swift:
   - Línea 89 en `value(of:)`:
     `precondition((running === self || running.graphTag == self.graphTag) && id.graphTag == graphTag, ...)`
   - Mismo principio que en `beginRead`: mantiene el aislamiento estricto entre grafos independientes y permite la lectura cruzada de atributos débiles únicamente entre handles del mismo grafo compartido.

Anteriormente, el test `i2_independentGraphsCannotReadEachOther` estaba marcado como `.disabled` porque al ejecutarse en el mismo proceso de la suite disparaba la precondición y abortaba la suite completa.

Se ha actualizado el test en `Tests/SwiftAttributeGraphTests/Unit/SharedGraphSpecTests.swift` para ejecutarse con:
```swift
@Test
func i2_independentGraphsCannotReadEachOther() async {
    await #expect(processExitsWith: .failure) {
        let g1 = Graph()
        let g2 = Graph()
        let input1 = g1.makeInput(100)
        let rule2 = g2.makeRule { g1.value(of: input1) }
        _ = g2.value(of: rule2)
    }
}
```
